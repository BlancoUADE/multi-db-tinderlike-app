DETALLES:

🐘 PostgreSQL (Relacional)
   - 12 tablas: usuarios, intereses, usuario_intereses, fotos, likes, 
     coincidencias, mensajes, bloqueos, eventos, asistencia_eventos, 
     notificaciones, dias_festivos
   - Contiene: Todos los datos con integridad referencial
   - Comando: SELECT * FROM usuarios;
   - Ve: Usuarios, intereses, likes, matches, mensajes

🍃 MongoDB (Documentos)
   - 1 colección: "perfiles"
   - Contiene: Documentos JSON desnormalizados (perfil completo)
   - Comando: db.perfiles.find();
   - Ve: Perfiles con intereses y fotos embebidas

🔴 Redis (Cache en memoria)
   - Claves: notificaciones:sin_leer:{id}, likes:contador:{id}, etc.
   - Contiene: Contadores, sesiones, datos con TTL
   - Comando: KEYS * ; GET notificaciones:sin_leer:1
   - Ve: Contadores actualizados en tiempo real

🔷 Cassandra (Time-series)
   - Keyspace: tinder_app
   - Tabla: mensajes_timeline
   - Contiene: Timeline de mensajes ordenada por tiempo
   - Comando: SELECT * FROM tinder_app.mensajes_timeline;
   - Ve: Mensajes en orden cronológico

🔗 Neo4j (Grafo)
   - Nodos: Usuario
   - Relaciones: DIO_LIKE, MATCH, BLOQUEÓ, ENVIÓ_MENSAJE
   - Contiene: Relaciones entre usuarios
   - Comando: MATCH (u:Usuario) RETURN u;
   - Ve: Nodos y conexiones de likes/matches

═══════════════════════════════════════════════════════════════════════════════

¿QUÉ SIGNIFICA "CADA DB TIENE UN TIPO DE DATO DISTINTO"?

PostgreSQL       → Datos relacionales (ESTRUCTURA)
MongoDB          → Documentos JSON (LECTURA RÁPIDA)
Redis            → Clave-valor / Contadores (VELOCIDAD)
Cassandra        → Time-series de eventos (ESCRITURA RÁPIDA)
Neo4j            → Relaciones entre nodos (CONSULTAS DE GRAFO)

Cada una es especialista en su tipo de dato y acceso.

¿SE RESPETÓ EL DER?

SÍ. El DER contiene estas entidades:

  USUARIOS
  ├── Intereses (relación M:N)
  ├── Fotos (1:N)
  ├── Likes (1:N)
  ├── Coincidencias (M:M)
  ├── Mensajes (1:N)
  ├── Bloqueos (1:N)
  └── Notificaciones (1:N)

Validar en PostgreSQL:
  \d usuarios          → Ver columnas
  \d fotos             → Ver tabla y FKs
  SELECT constraint_name, constraint_type FROM information_schema.table_constraints 
  WHERE table_name='usuarios';

¿Algo no funciona?

❌ "No se conecta a PostgreSQL"
   docker ps → ver si los contenedores están UP
   docker logs postgres → ver errores

❌ "No hay datos después de cargar demo"
   python main.py
   → Opción 20: Limpiar bases (con rollback)
   → Opción 19: Cargar demo de nuevo

❌ "Cassandra error en Python 3.12"
   Normal. Usa Python 3.11 si necesitas Cassandra, o ignora (la app sigue funcionando)
